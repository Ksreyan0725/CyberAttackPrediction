5. FUNCTIONAL REQUIREMENTS

A functional requirement strictly defines a specific behavior or function of a software system. Unlike non-functional requirements, which judge the operation or internal qualities of the system (such as speed and reliability), functional requirements explicitly describe what the system must actually "do." Within the CyberShield predictive architecture, the functional requirements mandate a complex, multi-stage analytical pipeline. The system must seamlessly bridge the gap between raw data ingestion at the networking layer, extremely deep statistical analysis at the machine-learning layer, and human-readable interpretation at the presentation layer. These ten functional requirements represent the absolute baseline code operations that the Python and Flask backend infrastructure must execute perfectly to successfully predict and categorize adversarial network activity in real-time environments.

5.1 SYSTEM FUNCTIONAL REQUIREMENTS (DETAILED)

1. High-Speed Ingestion of Network Traffic PCAPs
The foundational functional requirement of the entire architecture is the ability to ingest raw Packet Capture (PCAP) data or globally standardized CSV feature mappings (such as the NSL-KDD formats) accurately. The system must possess a dedicated data-loading subroutine capable of parsing millions of lines of network traffic logs simultaneously without overflowing memory buffers or dropping critical packets. This requires the backend to instantiate sophisticated Pandas DataFrames, ensuring that strictly numerical parameters (like source byte count) are immediately separated from categorical parameters (like TCP protocol types and service designations) exactly at the point of ingestion.

2. Multi-Stage Feature Extraction and Normalization
Once the raw data is successfully loaded into the application's memory space, the system must autonomously execute a highly complex, multi-stage mathematical preprocessing pipeline. The data provided by network interfaces is inherently chaotic and improperly scaled. Wait times might be measured in nanoseconds, while packet widths are measured in thousands of bytes. If this raw data were fed directly to the machine learning algorithms, the extreme variances would permanently bias the decision trees. Therefore, the architecture functionally mandates the use of strict scaling pipelines—primarily utilizing Scikit-Learn's StandardScaler and MinMaxScaler functionalities—to compress every single numerical feature into a uniform mathematical distribution explicitly bounded across a standard deviation matrix, ensuring optimal machine reading capability.

3. Attack Signature Embedding Generation
Following the numerical scaling, the system must properly translate human-readable categorical strings into machine-readable mathematical arrays through a process known as embedding generation or categorical encoding. Specifically, network traffic utilizes distinct string text for protocols (e.g., 'udp', 'tcp', 'icmp') and service statuses (e.g., 'http', 'private', 'ssh'). The functional requirement dictates that the model cannot process strings. Thus, the system must deploy automated algorithms like Label Encoding or high-dimensional One-Hot Encoding to perfectly transform these string variables into robust numerical matrices, effectively placing the categorical data mathematically alongside the scaled numerical data, creating a holistic uniform input array for the downstream prediction nodes.

4. Correlation Computation and Feature Selection
With over forty unique statistical variables representing every single network packet connection, injecting all available data blindly into the classification logic causes catastrophic processing latency and massive model overfitting. The system is functionally required to perform dynamic Correlation Computation. Using advanced Pearson or Spearman correlation techniques, the system must automatically analyze the dataset and strip away highly redundant features or 'static noise'. If the system mathematically determines that 'src_bytes' strongly mimics 'dst_bytes' during a specific Denial of Service attack iteration, the system must algorithmically prune the redundant features, minimizing the input space exclusively down to the most mathematically potent, predictive indicators.

5. Attack Probability Estimation using Stacking Ensemble
The absolute core function of the CyberShield platform is the execution of the predictive logic. The system must algorithmically process the normalized, selected feature arrays through a massive Stacking Ensemble classifier. The system is required to autonomously instantiate multiple, highly diverse base algorithms—specifically Random Forests, Decision Trees, and Adaptive Boosting parameters. The inputs must be evaluated by these baseline models individually, and their independent probability outputs must be subsequently fed into a Meta-Classifier (typically Logistic Regression or Extreme Gradient Boosting) to deliver the ultimate mathematical consensus over whether the network entity is 'Benign' or represents a specific attack taxonomy (e.g., 'Probe', 'DoS', 'U2R', 'R2L').

6. Threat-Level Aggregation across Network Segments
Once a packet or connection is accurately classified by the ensemble architecture, the system is functionally required to perform global threat-level aggregation. An isolated packet flagged as malicious might simply be an external internet scanner. However, when hundreds of packets are simultaneously predicted as malicious across multiple disparate subnets, the system must stitch these instances together. The architecture must actively maintain a temporal threshold counter. Once malicious predictions breach the defined limit within a specified timeframe, the internal system triggers a localized critical alarm state, officially elevating the threat status from an "Isolated Anomaly" to an "Active Persistent Attack."

7. Real-time Model Evaluation and Cross-Validation
Predictive models degrade heavily when confronted with shifting network typologies. Therefore, the system is functionally required to generate strict, real-time mathematical validation metrics upon the conclusion of every major classification batch. The program must explicitly calculate and log the global Accuracy, Precision, Recall, and F1-Score of its recent predictions. Most critically, it must actively construct and output a localized Confusion Matrix array, allowing administrative engineers to visually track exactly how many 'False Positives' (benign traffic blocked) or catastrophic 'False Negatives' (malware allowed to execute) the model is generating during current runtime execution.

8. SHAP-based Explainability and Visualization Reporting
Because modern machine learning implementations suffer significantly from "Black-Box" trust crises, the architecture is strictly required to implement Explainable AI (XAI) overlays. At the moment a severe threat is classified, the system must synchronously trigger the SHAP (SHapley Additive exPlanations) processing module. This algorithm must reverse-engineer the decision paths executed by the ensemble forest and produce an explicit, visually discernible graph explicitly detailing precisely what fraction of the prediction was influenced by specific node features (e.g., proving exactly how the 'duration' parameter outweighed the 'service' parameter).

9. Interactive Security Command Center Interface
All backend capabilities are rendered functionally useless if they cannot be easily digested by a tier-1 human SOC analyst. The system must support the execution of a locally hosted Flask web interface that acts as the Interactive Security Command Center. This component must accept uploaded traffic datasets from the user, route the raw data to the backend ML pipeline via asynchronous REST API calls, and beautifully render the returned predictive analytics. The interface is required to provide highly intuitive layout designs charting the proportion of attack classes mapped against benign traffic perfectly to improve rapid human intervention.

10. System Scalability and Encrypted Data Transmission
As a final functional mandate, the processing architecture must be explicitly designed for operational scalability within heavily restricted environments. While the Python model is entirely functional within isolated, single-host domains, the logic must support serialized extraction via tools like 'Joblib' or 'Pickle'. This guarantees that predicting algorithms can be instantly loaded into memory vectors without requiring full pipeline retraining. Furthermore, all dataset hand-offs between the user front-end interface and the backend decision trees must be perfectly secured against prompt injection or memory-buffer exploitation, guaranteeing extreme resilience against adversarial exploitation directed at the firewall layer itself.
