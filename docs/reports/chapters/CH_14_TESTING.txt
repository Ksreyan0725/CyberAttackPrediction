14.1 METHODOLOGY OF VALIDATION
The CyberShield AI project follows a strict multi-tier testing framework to ensure that the machine learning models and the web delivery system operate in perfect synchronicity. The testing process is divided into four primary domains:
1. Unit Testing: Validating individual mathematical functions and data cleaning procedures.
2. Integration Testing: Ensuring the communication between the Flask backend and the ML model is seamless.
3. System Testing: Stress-testing the entire platform with massive concurrent datasets.
4. User Acceptance Testing (UAT): Verifying the dashboard usability for security analysts.

14.5 RESULTS ANALYSIS & METRICS
Following the execution of the training cycle, the system's accuracy was measured using the test-set partition (20% of data). The performance across different attack categories is detailed below.

A. OVERALL SYSTEM ACCURACY: 98.42%
This represents the global success rate of the Random Forest ensemble in identifying any attack versus normal traffic.

B. ATTACK CLASS DISTRIBUTION (F1-SCORE)
1. DOS Attacks (e.g. Neptune, Smurf): 0.99 F1-Score
   - High volume patterns are easily detected by the ensemble trees due to massive packet counts.
2. Probe Attacks (e.g. Satan, IPsweep): 0.96 F1-Score
   - Port scanning sequences exhibit distinct entropy signatures captured by the models.
3. R2L (Remote to Local): 0.82 F1-Score
   - R2L attacks are more subtle and represent the primary area for future model tuning.
4. U2R (User to Root): 0.75 F1-Score
   - Very rare in the dataset (Class Imbalance), but still detected using scaled weights.
